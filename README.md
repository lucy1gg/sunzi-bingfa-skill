# 孙子兵法 Skill · 把一本书做成 Agent Skill

一个把《孙子兵法》十三篇完整结构化为 **AI Agent Skill** 的开源项目。
装进 `~/.codebuddy/skills/` 后，Agent 在遇到竞争、博弈、资源分配、团队管理类问题时
会自动加载它，引用原文并给出可执行的现代策略建议。

> 这不只是"电子书检索"。它做了三件事：
> ① **结构化**——十三篇原文完整入库，逐篇附要点与现代化迁移说明；
> ② **可调用**——一个"问题类型 → 篇目"的映射表，让 Agent 精准命中该查哪一篇；
> ③ **有约束**——明确的使用原则，防止把兵法生硬套到商业场景上，导致语义暴力化。

    └── 使用效果.md                  # 3 个真实案例实测：商业竞争 / 资源劣势 / 团队管理

## 安装

```bash
# 方式一：clone 后拷贝
git clone https://github.com/<your-name>/sunzi-bingfa-skill.git
cp -r sunzi-bingfa-skill ~/.codebuddy/skills/sunzi-bingfa

# 方式二：只要 skill 本体
mkdir -p ~/.codebuddy/skills/sunzi-bingfa
cp SKILL.md ~/.codebuddy/skills/sunzi-bingfa/
cp -r references ~/.codebuddy/skills/sunzi-bingfa/
```

安装后重启会话即可生效。

## 怎么用

直接问，不需要显式点名 skill：

- 「我们资源只有头部对手的十分之一，同赛道怎么打？」
- 「要不要进入一个已经很卷的赛道？」
- 「团队连续加班两个月，士气崩了，怎么办？」
- 「帮我用孙子兵法的框架分析这次谈判。」

Agent 会自动命中并给出**篇目定位 → 原文引用 → 现代化解读 → 可执行建议**四段式回答。

## 场景映射表（节选自 SKILL.md）

| 问题类型 | 优先篇目 | 核心原则 |
|---------|---------|---------|
| 要不要进入某市场/项目 | 始计、作战 | 五事七计；兵贵胜不贵久 |
| 正面硬碰还是绕开 | 谋攻、虚实 | 上兵伐谋；避实击虚 |
| 资源少、对手强 | 虚实、军形 | 致人而不致于人；先为不可胜 |
| 团队管理、执行落地 | 兵势、九地 | 势险节短；上下同欲 |
| 谈判、博弈、心理战 | 谋攻、九变 | 不战而屈人之兵；君命有所不受 |
| 风险识别与情报 | 行军、用间 | 相敌三十二法；先知必取于人 |
| 环境/赛道选择 | 地形 | 六形六法（通、挂、支、隘、险、远） |

## 效果预览

| 维度 | 不装 skill | 装了 skill |
|------|-----------|-----------|
| 引用准确性 | 凭记忆，易出错 | 取自原文库，可核对 |
| 回答结构 | 想到哪说到哪 | 篇目 → 原文 → 迁移 → 行动 |
| 可操作性 | 停留在结论 | 落到"做什么/不做什么/怎么衡量" |
| 跨界迁移 | 易暴力套用 | 有明确语义转换规则 |

## 设计取舍

- **为什么用"映射表"而不是把所有原文塞进 SKILL.md**：
  Skill 的 description 决定它什么时候被加载，正文越精炼越好在上下文里存活；
  大段原文放 `references/`，用到时才读，避免污染上下文。
- **为什么强调"不做鸡汤"**：孙子的内核是**成本计算**与**风险控制**，
  不是"心诚则灵"。所有建议必须能落到代价、收益、时间。
- **为什么单独写"使用原则"**：兵法用于战争，商业不是战争。
  Skill 里明确规定把"歼灭"转译为"获取份额"，把"间谍"转译为"市场调研"，
  去掉暴力语义——这是防止误用的关键。
